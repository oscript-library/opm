# opm
[![GitHub release](https://img.shields.io/github/release/oscript-library/opm.svg)](https://github.com/oscript-library/opm/releases)

OneScript Package Manager

Возможные команды:
- build    - Собрать пакет из исходников
- run      - Выполнить произвольную задачу
- test     - Выполнить тестирование проекта
- prepare  - Подготовить новый каталог разрабатываемого пакета
- install  - Выполнить установку. Если указано имя пакета, происходит установка из хаба или из файла. В обратном случае устанавливаются зависимости текущего пакета по файлу packagedef.
- update   - Обновить пакет
- app      - Создать bat-файл для запуска скрипта в указанном каталоге
- config   - Задать пользовательские настройки
- list     - Вывести список пакетов
- help     - Справка по командам
 
Наберите *opm <команда> --help*, чтобы вывести справку по команде

Справка из википедии: [Система управления пакетами](https://ru.wikipedia.org/wiki/%D0%A1%D0%B8%D1%81%D1%82%D0%B5%D0%BC%D0%B0_%D1%83%D0%BF%D1%80%D0%B0%D0%B2%D0%BB%D0%B5%D0%BD%D0%B8%D1%8F_%D0%BF%D0%B0%D0%BA%D0%B5%D1%82%D0%B0%D0%BC%D0%B8)

# Адрес хаба прямо в команде

Установка принимает адрес пакета в хабе вместо имени либо хаб опцией `--hub` и пул опцией `--pool`
(переменные окружения `OPM_HUB` и `OPM_POOL`), публикация — только опциями; без `--hub` — хаб по умолчанию,
без `--pool` — пул хаба по умолчанию; запись в `opm.cfg` не нужна:

```sh
opm install localhost:3380/corp/my-package@stable   # хост, порт, пул, пакет, тег
opm install hub.example.com/asserts                 # пакет в пуле хаба по умолчанию
opm install https://hub.example.com/public/asserts  # схема указана явно
opm install --hub localhost:3380 --pool corp my-package@stable
opm push --hub localhost:3380 --pool corp my-package-1.0.0.ospx
opm push --hub https://hub.example.com --token <токен> my-package-1.0.0.ospx
```

Адрес пакета: `[схема://]хост[:порт]/[пул/]пакет[@спецификация]`; в `--hub` — `[схема://]хост[:порт]` без пути.

* В адресе пакета последний сегмент пути — пакет, сегмент перед ним — пул; без пула — пул хаба по умолчанию.
  Зависимости пакета ставятся с того же сервера, у `install --hub` — с хаба из опций.
* Отказ: путь в `--hub`, адрес пакета вместе с `--hub`, `install --hub` вместе с `-a`, `-f`, `-u`, `-m`.
* Строка считается адресом, если в ней есть схема либо путь после хоста с портом, с точкой в имени
  или `localhost`. Остальное — имя пакета.
* Без схемы берётся `http` для `localhost`, `127.*` и адреса с явным портом, иначе `https`.
* Авторизация берётся у сервера из `opm.cfg` с тем же адресом и портом.
* `opm push --hub` отправляет токен из опции `--token` (переменная окружения `GITHUB_OAUTH_TOKEN`)
  или из настройки `ТокенПубликацииПакетов`. Канал при публикации в такой хаб необязателен.
* Опция `-m|--mirror` у `push` устарела и печатает предупреждение: вместо неё — `--hub`.
* `opm push --force` просит хаб опубликовать поверх уже занятого номера версии (параметр `force=1`
  в запросе публикации); перезапишет ли он версию, решает хаб.

# Версия пакета после @

`install`, `update` и `download` принимают после `@` точную версию, имя тега или выражение версии:

```sh
opm install vrunner@1.0.0     # точная версия
opm install vrunner@stable    # версия под тегом
opm install vrunner@^1.4      # старшая версия, подходящая под выражение
opm install vrunner           # версию выбирает хаб
```

Спецификация уходит хабу параметром `?spec=`, имя файла в адресе прежнее — `<пакет>-<спецификация>.ospx`.
Тег и выражение версии разрешает только хаб, принимающий `spec`; хаб без него отвечает 404, и opm так и говорит.
Точная версия ставится с любым хабом. Файловый сервер (`file://`) отдаёт только файл названной версии
и не подставляет вместо неё старшую.

К запросу файла пакета opm добавляет параметр `engine` — версию установленного OneScript. Хаб, который его понимает,
выбирает версию под этот движок там, где версию выбирает он (без `@`, тег, выражение); точная версия отдаётся как есть.
Если хаб отказал и объяснил причину в ответе, opm показывает её.

# Ошибки связи

Если хаб ответил, но файла не отдал, причина называется по коду ответа: 404 — файл не найден,
401 и 403 — отказ в доступе, иначе — код ответа и имя файла.

```console
$ opm install my-package
Ошибка установки пакета my-package: файл my-package.ospx в хабе не найден
```

Если ответа нет, opm называет адрес сервера: `Не удалось подключиться к http://hub.example.com:3380`.
Исходное описание ошибки уходит в отладочный журнал `oscript.app.opm`. При переборе нескольких
серверов из `opm.cfg` недоступный сервер остаётся предупреждением, и поиск идёт дальше.

# Проверка контрольной суммы

Хаб присылает sha256 файла пакета в заголовке `X-Checksum-Sha256`. opm сверяет с ним скачанный `.ospx`
и при расхождении отказывает в установке, не записывая файл. Ответ без заголовка (хаб без его поддержки,
файловый сервер) не сверяется.

# Сервера
В настоящее время пакеты хранятся на двух серверах:
- [hub.oscript.io](http://hub.oscript.io/download) - основной хаб пакетов
- [hub.oscript.ru](http://hub.oscript.ru/download) - вторичный хаб пакетов. Используется, когда не удаётся получить данные с основного хаба

# Особенности обновления версий 

## с 0.14.х на 0.15.х и выше

* Изменена строка использования (вызова) приложения - теперь соответствует стандарту POSIX. 
* Все параметры вызова разделены на опции и аргументы. Для коротких (1 символ) опций обязательно использование `-`, для длинных опций (2 символа и более) - использование двойного тире `--`
* Сначала необходимо указывать опции, а потом аргументы

Пример изменений использования для команды `build`
```sh
# версия 0.14.х и младше

opm build . -mf ./packagedef

# версия 0.15.x и старше

opm build --mf ./packagedef .

```

# Настройка

## Настройка путей установки скриптов
Переменная окружения ```OSCRIPTBIN``` отвечает за переопределение пути установки скриптов при глобальной установке. По умолчанию для linux считается "/usr/bin", а для windows КаталогПрограммы(). 
При указании данной переменной можно переназначить путь для создания скриптов запуска различных пакетов. Возможно скачать архив, распаковать его и запуская oscript с указанием этих переменных тестировать работу автономной установки. 
- **linux** 
```
OSCRIPTBIN=~/.local/bin opm update --all
```
- **windows** 
```
set OSCRIPTBIN=c:\temp\ 
opm update --all
```

## Настройка прокси-сервера для скачивания пакетов

Настройка производится с помощью создания служебного файла [opm.cfg](./tests/fixtures/opm-example.cfg) данный файл настроек можно расположить по таким путям (список приведен в порядке убывания приоритета):
 - ```./opm.cfg``` - текущий каталог запуска + /opm.cfg
 - каталог настроек пользователя
    - linux: ```~/.opm.cfg```, **внимание файла должен называться с точкой ```.opm.cfg```**
    - windows: ```%USERPROFILE%\opm.cfg```
 - системная настройка:
    - linux: ```/etc/opm.cfg```
    - windows: ```c:\ProgramData\opm.cfg```
- OSCRIPT/lib/opm/opm.cfg - каталог установки opm, для совместимости.

## Обновление

Пакетный менеджер обновляется вместе с oscript'ом, необходимую версию которого можно вручную скачать со страницы https://oscript.io/downloads/ или через [ovm](https://github.com/oscript-library/ovm), или обновить opm через сам opm:
```
opm update opm
```
